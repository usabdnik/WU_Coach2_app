# Feature Specification: Training Journal (Тренерский журнал)

**Feature Branch**: `008-training-journal`
**Created**: 2026-02-20
**Status**: Draft
**Input**: User description: "Мобильный тренерский журнал для быстрого просмотра и ввода результатов упражнений (подтягивания, отжимания, брусья) по группам учеников в одном экране. Таблица учеников с ячейками значений за текущий месяц, фильтрация по группе и наличию значений, быстрый ввод тапом по ячейке. Оптимизация рабочего процесса тренера на тренировке."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр журнала группы (Priority: P1)

Тренер открывает журнал, выбирает группу (например, М-19) и видит таблицу: слева — имена учеников, справа — три столбца (Подтягивания, Отжимания, Брусья) со значениями за текущий месяц. Пустые ячейки означают, что результат ещё не принят. Тренер сразу видит, сколько учеников в группе и у скольких уже приняты результаты.

**Why this priority**: Основная ценность фичи — видеть всех учеников и их результаты в одном экране без переключений между карточками.

**Independent Test**: Открыть журнал, выбрать группу, убедиться что все ученики группы отображаются с корректными значениями за текущий месяц.

**Acceptance Scenarios**:

1. **Given** тренер на главном экране, **When** открывает журнал и выбирает группу М-19, **Then** видит таблицу со всеми учениками группы и их значениями подт/отж/бр за текущий месяц
2. **Given** у ученика есть значение подтягиваний за текущий месяц, **When** тренер просматривает журнал, **Then** значение отображается в соответствующей ячейке
3. **Given** у ученика нет значений за текущий месяц, **When** тренер просматривает журнал, **Then** ячейки показывают прочерк (—)
4. **Given** тренер просматривает журнал, **When** смотрит на заголовок, **Then** видит счётчик "Принято: X/Y" (X — кол-во учеников хотя бы с одним значением, Y — всего в группе)
5. **Given** у ученика есть результаты за несколько месяцев, **When** тренер просматривает журнал, **Then** под текущим значением видит личный рекорд (максимум за все месяцы) для каждого упражнения

---

### User Story 2 - Быстрый ввод результата (Priority: P1)

Тренер тапает по пустой ячейке (например, "Отжимания" у Иванова), появляется поле ввода числа с клавиатурой, тренер вводит значение и подтверждает. Значение сохраняется, ячейка обновляется. Тренер переходит к следующему ученику без дополнительных шагов.

**Why this priority**: Быстрый ввод — ключевое преимущество перед текущим процессом (открыть карточку → найти месяц → ввести → закрыть → следующий ученик).

**Independent Test**: Тапнуть по пустой ячейке, ввести число, убедиться что значение сохранено и отображается.

**Acceptance Scenarios**:

1. **Given** ячейка пустая, **When** тренер тапает по ней, **Then** появляется поле ввода числа с числовой клавиатурой
2. **Given** поле ввода активно, **When** тренер вводит число и подтверждает (Enter или кнопка), **Then** значение сохраняется в localStorage и отображается в ячейке
3. **Given** ячейка содержит значение, **When** тренер тапает по ней, **Then** может изменить значение (поле предзаполнено текущим значением)
4. **Given** тренер ввёл значение, **When** сохранение произошло, **Then** счётчик "Принято" обновляется, изменение попадает в очередь pendingChanges

---

### User Story 3 - Фильтрация по наличию значений (Priority: P2)

Тренер хочет видеть только тех учеников, у которых уже принято определённое упражнение (например, подтягивания), чтобы понять, кому осталось принять отжимания и брусья. Или наоборот — показать только тех, у кого ещё нет подтягиваний.

**Why this priority**: Позволяет тренеру быстро организовать очередь на тренировке — сначала принять одно упражнение у всех, потом переключиться на следующее.

**Independent Test**: Включить фильтр "Есть подтягивания", убедиться что отображаются только ученики с заполненной ячейкой подтягиваний.

**Acceptance Scenarios**:

1. **Given** журнал группы открыт, **When** тренер включает фильтр "Есть подтягивания", **Then** отображаются только ученики с непустым значением подтягиваний
2. **Given** журнал группы открыт, **When** тренер включает фильтр "Нет подтягиваний", **Then** отображаются только ученики без значения подтягиваний
3. **Given** фильтр активен, **When** тренер вводит значение ученику, **Then** список обновляется в реальном времени (ученик может появиться или исчезнуть из фильтрованного списка)

---

### User Story 4 - Мультигрупповой просмотр (Priority: P3)

Тренер выбирает несколько групп одновременно (например, М-19 и М-117), чтобы видеть учеников из обоих групп в одном журнале. Полезно, когда на одной тренировке присутствуют ученики из разных групп.

**Why this priority**: Дополнительная гибкость для случаев смешанных тренировок, но основной сценарий — работа с одной группой.

**Independent Test**: Выбрать две группы, убедиться что ученики обеих групп отображаются в журнале.

**Acceptance Scenarios**:

1. **Given** журнал открыт, **When** тренер выбирает несколько групп, **Then** в таблице отображаются ученики из всех выбранных групп
2. **Given** выбрано несколько групп, **When** тренер смотрит список, **Then** ученики визуально разделены по группам (подзаголовки или цветовая группировка)

---

### Edge Cases

- Что если у ученика нет назначенной группы? — Ученик не отображается в журнале (журнал работает только с группами)
- Что если группа пустая (нет учеников)? — Отображается сообщение "Нет учеников в группе"
- Что если тренер вводит 0 или отрицательное число? — Значение 0 допустимо (сброс), отрицательные отклоняются
- Что если тренер вводит нечисловое значение? — Поле ввода принимает только числа (числовая клавиатура)
- Что если данные не синхронизированы (offline)? — Значения сохраняются в localStorage, синхронизация при следующем sync

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА отображать табличный журнал с именами учеников и тремя столбцами упражнений (Подтягивания, Отжимания, Брусья)
- **FR-002**: Система ДОЛЖНА показывать значения за текущий месяц текущего сезона для каждого ученика
- **FR-003**: Система ДОЛЖНА позволять фильтровать учеников по группе (одной или нескольким)
- **FR-004**: Система ДОЛЖНА позволять фильтровать учеников по наличию/отсутствию значений конкретного упражнения
- **FR-005**: Система ДОЛЖНА позволять вводить/изменять значение тапом по ячейке с появлением числового поля ввода
- **FR-006**: Система ДОЛЖНА сохранять введённые значения в localStorage немедленно и добавлять в очередь pendingChanges для синхронизации
- **FR-007**: Система ДОЛЖНА отображать счётчик прогресса "Принято: X/Y" для текущей группы
- **FR-008**: Система ДОЛЖНА обновлять таблицу в реальном времени при вводе значений (без перезагрузки)
- **FR-009**: Система ДОЛЖНА обеспечивать навигацию к журналу через нижнее меню или кнопку на главном экране
- **FR-010**: Пустые ячейки ДОЛЖНЫ отображаться как прочерк (—) для визуального отличия от нулевого значения (0)
- **FR-011**: Система ДОЛЖНА поддерживать работу в offline-режиме (данные из localStorage)
- **FR-012**: Система ДОЛЖНА отображать личный рекорд ученика (максимум за все месяцы сезона) для каждого упражнения рядом с текущим значением
- **FR-013**: Рекорд ДОЛЖЕН визуально отличаться от текущего значения (меньший шрифт, другой цвет) и обновляться при вводе нового значения, превышающего рекорд

### Key Entities

- **Журнал (Journal View)**: Табличное представление учеников группы с результатами за текущий месяц. Объединяет данные из athletes, exercises и performances.
- **Ячейка результата (Result Cell)**: Пересечение ученика и упражнения. Содержит числовое значение или пусто. Интерактивна — тап открывает поле ввода.
- **Фильтр упражнения (Exercise Filter)**: Критерий отображения учеников по наличию/отсутствию значения конкретного упражнения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Тренер может просмотреть результаты всей группы (до 30 учеников) в одном экране без горизонтальной прокрутки
- **SC-002**: Ввод результата одному ученику занимает менее 5 секунд (тап → число → подтверждение)
- **SC-003**: Переключение между группами происходит менее чем за 1 секунду
- **SC-004**: Время принятия результатов у группы из 15 учеников по 3 упражнениям сокращается минимум на 50% по сравнению с текущим процессом (карточки по одному)
- **SC-005**: 100% введённых данных сохраняются корректно в offline-режиме и синхронизируются при следующем подключении
- **SC-006**: Фильтрация по наличию/отсутствию значений обновляет список менее чем за 500мс

## Assumptions

- Три основных упражнения (подтягивания, отжимания, брусья) зафиксированы и не меняются
- Значения — целые числа (количество повторений)
- Один результат на ученика на упражнение в месяц (как в текущей системе performances)
- Текущий месяц определяется по сезонному календарю (Сент-Авг)
- Группы учеников уже назначены и доступны в данных (поле group/group_name)
- Журнал использует те же данные athletesData/exercisesData/performances что и основное приложение
